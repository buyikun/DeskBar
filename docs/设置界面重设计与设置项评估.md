# DeskBar 设置界面重设计：设置项必要性与合理性评估

> 评估对象：`src/DeskBar/Services/AppSettings.cs` 里当前全部设置字段，以及 `src/DeskBar/Views/SettingsWindow.xaml` 呈现的五页界面。
> 判定口径：**保留**＝必要且合理；**改造**＝保留能力但需修表现；**移除**＝无消费方或重复；**新增**＝用户真实需要但原界面缺失。

## 二、核心问题：为什么「自动主题」看不到白天/夜晚各是什么主题

这是用户报告的原话问题，根因有三层，缺一不可。

### 根因 1：`auto` 是个硬编码别名，根本没有可选的昼夜配置

改前 `NativeTaskbarAppearanceService.GetColorForTone` 里：

```csharp
"auto" => IsSystemInLightTheme() ? 0x25525252u : 0x25323232u,
```

即 `auto` 等价于「白天 = `softmist`（柔雾）、夜晚 = `sheertights`（黑丝）」，**写死在代码里**。设置界面把它标成「随系统自动（昼浅夜深）」，但用户既不能改白天用哪个、也不能改夜晚用哪个，甚至看不到这个映射关系。这就是「无法选择白天和夜晚是什么主题」的字面原因。

### 根因 2：`auto` 依赖系统深浅色，而系统深浅色又会被 DeskBar 改写，形成环路

`auto` 的输入是 `IsSystemInLightTheme()`（读 `HKCU\...\Personalize\SystemUsesLightTheme`），而 `ThemeService.SetTheme()` 在自动切换时**正是去写这个键**。于是：

- 用户手动把系统切成浅色 → `auto` 判定「现在是白天」→ 用柔雾；
- 到了 19:00，`ThemeService` 把系统改成深色 → `auto` 判定「现在是夜晚」→ 换成黑丝。

看起来「正常」，但这两个判断的驱动源其实是同一个注册表值，用户无法独立控制「界面深浅」和「任务栏色调」—— 想白天用深色界面 + 柔雾任务栏，做不到。

### 根因 3：半透明色调在界面上几乎看不见

即使把 5 个色调排成一行，`softmist` 的 alpha 只有 `0x25`（14.5%）、`sheertights` 是 `0x25`、`light` 是 `0xA0`、`dark` 是 `0x90`、`natural` 是 `0x00`。前两个把颜色叠加到任何背景上都几乎无差别，用户看到下拉框里写着「浅色柔雾」「深色黑丝」，屏幕上却分辨不出来。

### 解法

1. **把 `auto` 从色调枚举里删掉**（6 项 → 5 项），因为「随系统自动」这个语义现在由昼夜方案显式承担，两者并存会造成两个互相覆盖的入口。
2. **新增四个字段**：`DayThemeLight`、`NightThemeLight`、`DayAcrylicTone`、`NightAcrylicTone`。每个时段各自决定「界面浅/深」+「任务栏材质」，互不干扰。
3. **老配置平滑迁移**：`AppSettings.Normalize()` 里检测到 `AcrylicTone == "auto"` 时，写入 `DayAcrylicTone = "softmist"`、`NightAcrylicTone = "sheertights"`、`AcrylicTone = "natural"` —— 与旧 `auto` 的实际观感完全一致，老用户升级后不觉得「设置变了」。
4. **运行时覆盖机制**：`RuntimeTone`（`[JsonIgnore]`，不落盘）+ `EffectiveTone => RuntimeTone ?? AcrylicTone`。所有渲染路径（任务栏、音乐胶囊、监控浮岛、岛屿边框）统一读 `EffectiveTone`：自动主题开启时由 App 写入当前时段色调，关闭时置 null 交还用户手选值。这样「时段色调」不会覆盖用户的手选偏好。
5. **可视化**：自动主题页顶部放实时状态条，直接回答用户的原问题 —— 「现在是夜晚 · 深色界面 · 黑丝」「下一次切换：11-08 07:00 → 浅色界面 · 柔雾（2 小时 55 分后）」。昼夜两个方案各配一个色块预览。
6. **色块用设计软件通用的棋盘格表示法**：棋盘格露出的程度 = 透明度，色相 = 实际着色。`natural`（alpha=0）会露出完整棋盘格，表示「没有着色层」；`softmist`/`sheertights` 几乎全透，一眼就能看出「这两个很淡」。同时把色值和不透明度写进 ToolTip，并在下拉项文案里标出覆盖百分比（15% / 14% / 63% / 56% / 0%），把「几乎透明」这件事本身变成可见信息。

## 三、其余需要修的表现问题

### 时间输入：无校验、每敲一个字符就落盘

改前 `OnTimeConfigChanged` 绑在 `TextChanged` 上，用户输入 `0`、`07`、`07:`、`07:0`、`07:00` 的每一步都直接把字符串写进 `LightStartTime` 并 `Persist()`。而真正解析在 `App.xaml.cs` 里 `TimeSpan.TryParse`，失败就静默忽略 —— 用户打了非法值，界面毫无反馈，功能悄悄失效。

改后：

- 输入框失焦或按 Enter 才提交，Escape 撤销；
- 用 `AppSettings.TryNormalizeTime` 双向校验（含 `[0, 24h)` 范围、截掉秒毫秒）；
- 白天与夜晚相同会被拒绝：「白天与夜晚的开始时间不能相同，否则无法划分时段。」；
- 通过后把文本规整回 `HH:mm`，并显示「白天 12 小时 · 夜晚 12 小时」。

### 注入失败时的静默降级

`TaskbarService.StartIslandOrDegrade()` 在 `NativeTaskbarAppearanceService.IsAvailable == false` 时，只做 `RestoreTaskbarRegion()` + `StartWatchOnly()`，**不做任务栏裁剪** —— 否则会把开始区/搜索框/时钟整块挖掉。也就是说「居中止岛」在这种情况下是半失效的。

改前界面对此零提示。改后在外观页底部加运行态提示卡；模糊度接口回退时也提示「当前系统的任务栏模糊接口不可用」。

> **第二轮修正**：这一降级**与是否管理员权限无关**。原文与源码注释把原因写成 `0x80070005`／「非管理员必然如此」，属未经验证的历史断言。实际触发原因是 `ExplorerTAP.dll` 缺失、版本不匹配，或 Explorer 正在重启。相关注释与 `Log.Warn` 文案已全部改写，见第七节。

### 自动主题与手选色调的双向耦合

改前 `CmbAcrylicTone` 在自动主题开启时仍然可点，但点了没用（因为 `auto` 分支不看用户选择）。改后自动主题接管时把该下拉框置灰（`IsEnabled = false`，配 `Opacity 0.45` 触发器），并在旁边写「自动主题已接管色调，请到『自动主题』页分别为白天与夜晚指定材质」，附一条可跳转的说明。

### 「关闭窗口不退出进程」没有说明

`OnClosing` 里 `e.Cancel = true; Hide(); App.TrimMemory();` —— 点 X 只是隐藏。界面底部「隐藏到托盘」按钮其实和点 X 效果一样。已在页脚写明「所有设置即时生效并自动保存」，并在关闭按钮语义上保持「关闭」而非「退出」。

## 七、第二轮：管理员权限这套机制被实测证伪并删除

**起因**：用户看到托盘菜单的「启用管理员权限开机自启（根治磨砂丢失）」「以管理员身份重启（本次恢复磨砂）」和设置页的「以管理员权限自启 / 启用（需授权）」，问「如果没用的话就删掉吧」。

**取证（全部来自本机实测，非推理）**

| 检项 | 结果 |
|------|------|
| `deskbar-20261108.log` 启动诊断 | `Startup diag: is64=True user=Administrator identity=COMPUTER\Administrator **elevated=False**` —— 进程非提权 |
| 同一时刻的注入结果 | `Loading ExplorerTAP.dll from: D:\app\DeskBar\ExplorerTAP.dll` → `NativeTaskbarAppearanceService initialized successfully via COM.` → `SetTaskbarBlur available, blur=18` —— **注入成功** |
| 全日志 `degraded to geometry-only` 出现次数 | **0** |
| 全日志 `0x80070005` 出现次数 | **0** |
| 计划任务 | `Get-ScheduledTask -TaskName 'DeskBar*'` 无结果，**计划任务根本不存在** |
| 实际自启方式 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下 `DeskBar = "D:\app\DeskBar\DeskBar.exe"` —— 普通权限 Run 键 |
| UAC 配置 | `EnableLUA=1`、`ConsentPromptBehaviorAdmin=0`、`FilterAdministratorToken=1`，`IsInRole(Administrator)` 返回 **False**（过滤令牌） |
| 任务栏实拍 | `shots/taskbar_now.png`：居中止岛、托盘岛屿、左右浮岛组件全部正常生效 |

**结论**：Explorer 与本进程同为 Medium 完整性级别，同级别注入本就允许。「必须管理员权限才能接管任务栏外观」这个前提在这台机器上**不成立**。源码里所有关于 `0x80070005` 与「需要管理员身份运行」的注释、日志、UI 文案，都是未经验证的历史断言（源自老版 TranslucentTB 的包袱），被一路沿用下来。
